# ビルド失敗した原因と対処

今回のビルド失敗は、GCC 11.4.0がC++ソースコードのコンパイル中にSegmentation faultで異常終了したことが直接の原因です。
GCC 12.3.0に切り替えることでビルドが成功したため、GCC 11のコンパイラ内部の不具合、またはGCC 11と最適化条件の組み合わせに問題があった可能性が高いと考えられます。
1. 発生したエラー
試行	コンパイラ・条件	結果
1回目	GCC 11・通常ビルド	ndt_omp_ros2で異常終了
2回目	GCC 11・並列数1	ndt_omp_ros2成功、lidar_localization_ros2失敗
3回目	GCC 11・変数追跡無効化	lidar_localization_ros2失敗
4回目	GCC 12・並列数1・-g0	ビルド成功
特に次の2種類のエラーが発生しました。
① GCC内部の変数追跡処理で異常終了

```text
during RTL pass: vartrack
component_parameters.cpp:799:
internal compiler error: Segmentation fault
```


② Eigenの行列演算のコンパイル中に異常終了
```text
Eigen/src/Core/ProductEvaluators.h:389:
internal compiler error: Segmentation fault
```


いずれもinternal compiler errorであり、通常の構文エラーや型不一致とは異なります。
2. なぜGCC 11で失敗したのか
確認したlidar_localization_ros2のCMakeLists.txtには、次の設定があります。
SET(CMAKE_CXX_FLAGS "-O2 -g ${CMAKE_CXX_FLAGS}")


この設定により、GCCは最適化とデバッグ情報生成を行います。
また、プログラムではEigenを使用して複雑な行列演算を実装しています。EigenはC++テンプレートを多用するため、コンパイラに比較的大きな処理負荷がかかることがあります。
今回のログからは、GCC 11がこれらの処理中に異常終了したことが分かります。
ただし、GCC 11のバグだったと断定することはできません。 GCC 12への変更と同時に-g0などのビルド条件も変更しており、加えてメモリやハードウェアの一時的な問題も完全には否定できないためです。
3. メモリ不足が原因だった可能性
以前の確認では、以下の状態でした。
- 物理メモリ：15 GiB
- 使用可能メモリ：8.5 GiB
- スワップ：0 GiB
- OOM関連ログ：検出なし
ビルド中のメモリ使用量は測定していませんが、OOM Killerが動作した証拠はありません。
また、並列数を1に制限してもGCC 11では失敗しているため、単純な並列ビルドによるメモリ不足だけでは説明できません。
4. 今後の対応
今回、GCC 12で正常にビルドできているため、現時点ではソースコードの修正は不要です。
今後もGCC 12を使用することを推奨します。ただし、次の点は区別して管理するとよいでしょう。
- 実際に確認できた原因： GCC 11のコンパイルプロセスがSegmentation faultで異常終了した。
- 最も疑わしい根本原因： GCC 11と対象コード・コンパイル条件の組み合わせ。
- 有効だった対策： GCC 12への切り替えと-g0によるビルド。
なお、GCC 11だけに問題があるかを厳密に確かめるには、GCC 12で-g0を外しても成功するかなど、コンパイラ以外の条件を揃えた比較が必要です。
結論として、今回のビルド失敗をlidar_localization_ros2のソースコードの不具合として扱う必要はありません。 コンパイラ環境に起因する可能性が高い問題として記録しておくのが適切です。
